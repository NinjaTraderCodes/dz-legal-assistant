### Proxy decision for M2

The child environment remains an allowlist. Copy **HTTPS_PROXY** and **NO_PROXY** from the launching user's process environment into the managed engine only, adding `127.0.0.1,localhost,::1` to the bypass list. Do not copy HTTP_PROXY, ALL_PROXY, arbitrary certificate-file overrides, inherited OLLAMA settings or unrelated variables. This follows the [official Ollama proxy guidance](https://docs.ollama.com/faq#how-do-i-use-ollama-behind-a-proxy): model pulls use HTTPS; a corporate proxy certificate must already be trusted by Windows. The app does not install certificates or bypass TLS checks. Restart the app after changing user proxy settings.

The app's setup and inference clients still use `LoopbackGuard` with proxies and redirects disabled. Their case requests never enter the office proxy. Only a lawyer-initiated engine model download may use the proxy, and it contains model identifiers and public model bytes, not case data. Proxy values may contain credentials: do not display, persist or log them, process start arguments, raw engine output or raw pull errors. Raw stdout/stderr remains drained and discarded; the card uses localised error categories. An independently running Ollama keeps its own environment; it is not reconfigured. There is no automatic download, connection test or proxy discovery on startup. Offline packs remain the alternative when proxy/certificate setup is unavailable.

Added tests cover an older/equal/newer version, missing/malformed version responses, selected-model-only release on a reused server, and proxy allowlisting/bypass entries without weakening loopback. ## M3 — verified offline packs

Implemented Install model from a file and Save model to a file, with native local-file pickers and bilingual card states. Choosing a pack reads its identity and shows the corresponding original terms; installing it requires a separate click. Import checks the identity again at installation, so replacing the selected file cannot silently change the model whose terms were shown. The terms now have a separate bounded pane above the action buttons, visible even in Arabic at 1366×768. Cancel applies to downloads, import and export; Not now leaves an authorised operation running and keeps templates usable. Cancelled/failed export keeps a previously ready model usable unless integrity or RAM failed.

`.dzmodel` v1 contains `manifest.json` (the exact built-in bytes) and `blobs/sha256-<hash>` entries for its complete built-in inventory. There is no signing key and no user-supplied trust list. Extra/missing/duplicate/case-variant/traversal/absolute/backslash entries, symlinks, unexpected lengths, oversized metadata and excessive expansion are rejected. ZIP64 end-record and directory counts are bounded before the ZIP reader can use them; [PKWARE's format specification](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT) is the reference. Standard stored ZIP/ZIP64 packs are generated by the app. No arbitrary archive entry is extracted by its supplied path.

Import streams and hashes every archive blob, even when a local copy exists. Missing/repaired blobs are staged under the private model store; nothing is published until every blob matches. The canonical manifest is published last. A failed check/cancel leaves the previous manifest and existing blobs in place and removes only that operation's staging files. Verified blobs published before a later engine/self-test failure can be reused on retry. Import has no pull path: after file verification it starts/reuses only the private engine, checks local metadata/RAM, and runs the same short case-free self-test. Model inference stays with the existing provider and Gemma 4 thinking remains off.

Export reads only the chosen supported model's expected blobs from its local store, hashes them while writing an uncompressed temporary pack, and atomically publishes the completed file. A failed/cancelled export preserves an existing destination. It exports no draft, prompts, answers, profile, history, config or credentials. A FAT32 size error is explained; an exFAT/NTFS USB drive is suitable for the Gemma 4 pack. The app-store drive retains 2 GiB; a separate export drive needs the pack plus bounded archive headroom (not another 2 GiB). Import/export retain the 512 MiB memory guard and periodically recheck disk space. Unreadable installed blobs fail verification instead of blocking a fresh private-store acquisition; they are never accepted without their hash check.

Added checks: twenty pack-store cases covering round trip, exact contents, unsafe/corrupt inputs, ZIP64 count bounds, changed identity, cancellation, disk reserve, old-model preservation, repeated import verification and preservation of an existing export. View checks cover explicit installation after terms, export cancellation/template continuation, error sanitisation, asynchronous ready updates, all three selected-model outcomes and stale-check rejection. An unreadable-blob test covers failed file access. Existing tests are retained and strengthened, including assertions that terms are visible above Install/Download and that Not now remains within the window.
