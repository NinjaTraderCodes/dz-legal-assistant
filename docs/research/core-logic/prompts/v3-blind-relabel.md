# Blind relabelling of hidden set v3 and of the mirror set (Codex)

- **Model:** Codex, a fresh session per call (`--ephemeral`), 10 to 20 notes per call (the number the pilot showed to be free of sag), called **only by the command `v3 relabel`** ([../specs/hidden-v3-commands.md](../specs/hidden-v3-commands.md)). The command reads the notes inside the set's folder, sends their text in the prompt on standard input, writes the event log, the answer and Codex's standard error under `<root>\_codex\`, and prints counts only. `<root>` is `C:\dz-hidden-v3`, or `C:\Users\TheShadow\dz-core-research\mirror` for the mirror set (`--root`).
- **The prompt is [notes-judge.md](notes-judge.md), unchanged,** with the Codex output schema `schemas/notes-judge.schema.json`. There is deliberately no separate text: the hidden set's checker must apply the same guide in the same words as the open sets' judge, or the two measures would not be comparable.
- **Placeholders:** as in `notes-judge.md`. `{{notes}}` holds the four text fields of each note and a call-local number. **Never** the writer's labels, the plan, the note's id, or anything else from the folder.
- **Checks by the command:** the event-log rule; the schema; every quote found in the note; every element of the chosen claim types answered. A call that fails a check is rejected, by the one rule of [../specs/codex-calls.md](../specs/codex-calls.md) ("A rejected call: one rule, for every role"):
  - **Its answer is discarded**: not parsed, not stored. **The same prompt is never sent again automatically.** Its notes go back to the queue **once**, to be sent in a later call built afresh from the queue; a note whose second call is rejected too is set aside and reported (counted as "relabel invalid", apart from "disagreement"), never queued a third time.
  - **A rejection for tool use** (the model ran a command or opened a file) **is counted apart** from the other rejections. **On v3 (a hidden set): stop and tell the owner** (stop point "A suspected exposure of a hidden set"); nothing on v3 resumes before the owner's answer. On the mirror (an open set): fix the prompt before the next batch; since the prompt is `notes-judge.md`, shared with the open sets' judges, a fix is a change of the frozen method: report it, and start v3 only from a chain that produced no tool-use rejection on the mirror.
  - **Two consecutive failed calls of any kind stop the batch** (refused, rejected, timed out, or failed for a reason the script does not know). The command records where it stopped and why, as a fixed reason code; the builder reads the reason before the next batch starts.
  - A usage-limit refusal is not a rejection: it stops the batch at once, its notes stay where they are in the queue, and the next batch resumes from there. Never loop on a refusal.
- **Compare:** `v3 compare`, by the rules of the notes pipeline, with the test-set rule: **any disagreement, and any `unclear`, drops the note.**
- **What the builder sees:** `calls accepted: N`, `calls rejected tool use: N`, `calls rejected other: N`, `calls refused: N`, `notes relabelled: N`. Nothing else. The scratch folder of these calls is empty and outside the hidden folder. Nothing technical stops a Codex call from reading a folder at the root of `C:`; what protects the set is that the call is given no path, and that **the event-log rule discards any call in which Codex opened a file or ran a command.**
- **Before the first real call on v3:** the command passed its marker test on fixtures and on the mirror set: a marker string placed in the notes must appear in no console output and in no file outside `<root>`: the places checked are named in the specification, section 5 (`%TEMP%`, `%USERPROFILE%\.codex\`, the scratch and log folders, the worktree, the rest of `C:\Users\TheShadow\dz-core-research\`, the Windows Application event log).
